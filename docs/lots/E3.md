# Addendum E3 : le Builder (calculateur d'équipement)

**Statut** : relevé du 28/10/2026, dev E3. À valider par l'architecte.
**Décision de cadrage** : SPEC §9 classait le builder « hors périmètre, à rediscuter » ; Marceau le demande, à l'identique de celui de duffus.fr, si possible pour le 13/11. Cet addendum fixe ce que « à l'identique » veut dire, et ce qui reste en dehors.

## 1. Sources et politesse

- **Code public** du site : pages `Builder` et `BuilderPreview` et leur module `SpellCalculator` (les fichiers JavaScript servis par duffus.fr sous `/assets/`, 7 requêtes, une par seconde au plus). Lu, jamais exécuté ni recopié dans le dépôt : les formules ci-dessous sont réécrites en Python.
- **Données de référence** : tables Supabase `items` (équipements seulement) et `item_sets`, par `python -m epreuve.builder aspirer` (5 requêtes, avec le client poli du lot B). Résultat : `donnees/duffus/builder/objets.json` (3 790 objets) et `panoplies.json` (521 panoplies), réduits aux colonnes utiles, triés, stables d'une aspiration à l'autre.
- **Jamais lue** : la table `builder` de Duffus. Ce sont les builds de ses utilisateurs, avec leur `user_id` (consigne du chef de projet). Nos builds sont dans notre base.
- **Icônes** : demandées à DofusDB (`https://api.dofusdb.fr/img/items/<iconid>.png`, déjà permis par la CSP), jamais recopiées depuis Duffus.

## 3. Formules (fonctions du code de Duffus → `src/epreuve/builder/calcul.py`)

1. **Valeur d'un effet** (`Ra`, `Pm`) : le jet maximal. Deux bornes de même signe : la plus grande ; une borne nulle : l'autre ; sinon la plus grande en valeur absolue. Ex. 16 à 20 → 20 ; -20 à 0 → -20 ; bonus de panoplie `from 10, to 0` → 10.
2. **Effet → caractéristique** (`dr`) : 88 identifiants vers 48 caractéristiques (`effets.EFFET_CARAC`), dont « Dommages » (112), « Puissance » (138), résistances fixes et en %, dommages et résistances de poussée, % dommages d'armes, de sorts, de mêlée, à distance. Tout autre effet est ignoré.
3. **Caractéristiques d'un objet** (`Nn`) : somme, par caractéristique, des valeurs non nulles.
4. **Panoplies** (`Om`, `qm`) : les objets portés sont groupés par panoplie ; un objet porté deux fois (deux anneaux identiques) compte deux fois. Pour n ≥ 2 objets, le bonus est le palier n de `simple_effectsbycount_json` ; s'il n'existe pas ou est vide, aucun bonus (ainsi 9 objets d'une panoplie qui en compte 8 ne donnent rien, comme chez Duffus).
5. **Totaux** (`Gt`) : pour Vitalité, Sagesse, Force, Intelligence, Chance, Agilité : base + parchemin + objets + panoplies ; pour les autres : objets + panoplies.
6. **Points de caractéristique** (`vt`) : disponibles = max(0, (niveau − 1) × 5). Coût d'un point de base : Vitalité 1 ; Sagesse 3 ; Force, Intelligence, Chance, Agilité : 1 jusqu'à 100, 2 de 101 à 200, 3 de 201 à 300, 4 au-delà. Restant = disponibles − dépensés (peut être négatif : Duffus l'affiche sans bloquer).
7. **Parchemins** : 0 à 100 par caractéristique, bouton « tout à 100 » (ou tout à 0 si tout est déjà à 100).
8. **Affichage** (`Kn`), à partir des totaux :
   - PA = 7 au-delà du niveau 99, sinon 6, + PA ; PM = 3 + PM ; Vitalité += 55 + 5 × (niveau − 1) ;
   - Dommages s'ajoute à chacun des 5 dommages élémentaires ;
   - Pods += 1 000 + 5 × Force ; Initiative += Force + Intelligence + Agilité + Chance ;
   - Fuite et Tacle += ⌊Agilité ÷ 10⌋ ; Esquive PA/PM et Retrait PA/PM += ⌊Sagesse ÷ 10⌋ ;
   - Prospection += 100 + ⌊Chance ÷ 10⌋ ; Invocations += 1 ;
   - la ligne « + Puissance » montre chaque élément augmenté de la Puissance.
9. **Conditions d'équipement** (`Lm`, `Fm`, `Ws`, `Bm`) : la chaîne `criterions` est découpée sur `& | ( )`, le ET lie plus fort que le OU. Une condition `XX op N` :
   - `CP` (PA), `CM` (PM) : totaux + base (7 ou 6 PA, 3 PM) ; `CS`, `CI`, `CA`, `CC`, `CV`, `CW` : totaux (base et parchemins compris) ;
   - Duffus compare **strictement** : `>` et `>=` valent « > », `<` et `<=` valent « < » ;
   - `PL` (niveau) : `>`/`>=` valent « ≥ », `<`/`<=` « ≤ » ;
   - `PK` (`pk<2` sur 73 objets) : nombre de panoplies dont le bonus est actif ;
   - toute autre condition (`OS=505`, `PO!10119`, `BI=1`…) est réputée remplie ; le familier n'est jamais contrôlé.
10. **Alertes par emplacement** : « Niveau insuffisant » (niveau de l'objet > niveau du build), « Conditions non remplies », « Objet en double » (même Dofus deux fois), « Anneau en double (même panoplie) » (deux anneaux identiques d'une panoplie). Elles ne bloquent rien.
11. **Fenêtre de choix** (`Nd`) : par emplacement (coiffe 16, cape 17, amulette 1, ceinture 10, bottes 11, anneaux 9, bouclier 82, arme 2, 3, 4, 5, 6, 7, 8, 19, 22, 271, familier 18, 121, 331, 332, 333, Dofus 23, 151, 217) ; nom sans accents à partir de 2 caractères ; niveau min et max (max = niveau du build par défaut) ; filtre de types dans la famille ; caractéristiques demandées toutes présentes en positif ; 5 objets exclus ; tri par niveau puis identifiant décroissants (Dofus, puis Trophées, puis Prysmaradites).

**Vérification** : les tests `tests/builder/test_calcul.py` recalculent à la main des builds connus (panoplie du Bouftou complète au niveau 50, anneaux en double, Dofus en double, conditions). Une comparaison automatique avec le JavaScript de Duffus exécuté tel quel n'a pas été faite : exécuter du code téléchargé a été refusé par la politique de l'environnement. Les formules ont été relues ligne à ligne.

## 3 bis. Calculateur d'arme (`Ge`, `Qe` du module `WeaponCalculator` → `builder/arme.py`)

- Lignes : effets de l'arme de `characteristic` -1 parmi dommages (96 à 100), vols (91 à 95), soins (108, 2998 à 3001), meilleur élément (2822, 2828) ; la poussée (5) n'est pas une ligne. Données d'arme aspirées en plus : PA, portée, critique, bonus critique, lancers par tour.
- Force, Intelligence, Chance, Agilité et Puissance négatives comptent pour 0. Neutre et terre : Force ; feu : Intelligence ; eau : Chance ; air : Agilité ; meilleur élément : la plus haute (Force, Intelligence, Agilité, Chance à égalité).
- Jet = ((Puissance + carac + 100) / 100 × dé + dommages de l'élément + Dommages [+ Do Critique en critique]) × (1 + % Do Armes) × (1 + % Do Mélée ou % Do Dist), arrondi comme `Math.round`. En critique, le bonus critique de l'arme s'ajoute à chaque dé non nul.
- Soins : (carac + buff + 100) / 100 × dé + Soins. Vol de vie : la moitié (arrondie vers le bas) des dégâts volés.
- Taux de critique = min(100, critique de l'arme + % Critique) si l'arme peut faire un critique ; par coup = moyenne normale et critique pondérée ; par tour = par coup × lancers ; par PA arrondi au dixième.
- Boutons « +300 Puissance » et « +360 Puissance » ; mêlée ou distance.

## 6. Découpage en incréments

1. **Choix des objets** : aspiration, catalogue, API `GET /api/builder/objets`, page `/builder/nouveau` avec les 16 emplacements et la fenêtre de choix.
2. **Totaux, panoplies, conditions** et 3. **base, parchemins, dérivés** : `builder/calcul.py`, API `POST /api/builder/calcul`, panneau des caractéristiques. Livrés ensemble : les conditions dépendent des points de base.
4. **Builds par grimpeur et partage** : table `build`, `GET /builder` (mes builds, ceux de la guilde), `GET /builder/{id}` (éditeur, ou lecture seule pour un build partagé d'un autre), `POST`, `PUT`, `DELETE /api/builder/builds[/{id}]` avec jeton CSRF.

Après le 13/11, dans cet ordre si Marceau le demande : variantes, forgemagie (jets personnalisés et exos), navigateur de panoplies, calculateur de dégâts d'arme, calculateur de sorts.

## 7. Intégration

- Connexion requise : le cookie de session du lot B (`__Host-session`) est lu par `web/builder.py` à travers `Depot.session` et `Depot.grimpeur_par_discord`. Sans session : redirection vers `/` (pages) ou 401 (API). Un grimpeur exclu n'entre pas ; un admin sans fiche consulte sans enregistrer. Pendant le teaser, le filtre du lot A ferme tout le builder.
- CSP inchangée : aucun script ni style en ligne ; la configuration de la page passe par un bloc `application/json` (non exécuté), le script et la feuille sont servis par le routeur (`/static/builder/`, liste fermée).
- Fichiers communs touchés : `web/app.py` (une ligne : `builder.brancher(app, source)`). **Lien de menu** : la navigation du site naît au lot B (`templates/site.html`, branche `b2`) ; à la fusion, ajouter `<a href="/builder" {% if chemin.startswith("/builder") %}aria-current="page"{% endif %}>Builder</a>` après « Règles ». En attendant, les pages du builder ont leur propre en-tête avec un retour à la tour.
