# Lot F4 : la fiche de quête à parité avec Duffus (départ, étapes détaillées, suivi)

Étude faite le 29/10/2026 dans le code public de duffus.fr : le bundle `index-….js` puis les modules `QuestPage`,
`QuestTemplate` (le gabarit que charge `QuestPage`), `LecteurQuete` et `questPipRender` (5 requêtes de fichiers JS, une par
seconde au plus, `User-Agent` qui nous identifie). Une seule lecture de données : la colonne `quest_pages.quick`
(`slug`, `quick`), qui manquait. Aucune donnée d'utilisateur de Duffus n'a été lue (`user_quest` n'est cité que dans le code).

## Ce que la page de quête de Duffus affiche

`QuestPage` lit une ligne de `quest_pages` (`slug`, `published = true`) et la donne au gabarit `QuestTemplate`.

| Zone de la page | Source | Contenu |
|---|---|---|
| En-tête | `meta` | titre, **zone de départ** (`zone`), **PNJ de départ** (`startNpc`), **position** (`startCoords`, « [x,y] », un clic copie `/travel x,y`), niveau conseillé (`level`), « répétable » (`repeatable`), vignette de la carte de départ |
| Case « quête terminée » | `user_quest` (`done`) | une seule case par quête, pour le compte connecté ; pas de case par étape |
| Prérequis | `prereq_quests` (liens), `prereqs` (textes) | liens vers les quêtes, cochés « faite » pour le compte connecté |
| Étapes de la quête | `content_html` (+ `steps`, vide partout) | des blocs `qstep` : dialogue (PNJ, répliques à choisir), déplacement (**bouton `[x,y]` + phrase**), marche, clic, combat (**monstres avec quantités**), fiches de monstres, craft (objet fabriqué + recette avec quantités), « à prévoir » (**objets avec quantités**), donjon (« jusqu'à la 4e salle »), astuce, note, positions à cliquer dans l'ordre, enchaînement de quêtes |
| Infos rapides | `quick` | nombre de combats (solo, groupe, Songes, tactique, aléatoires), dalles, farm, combats à vagues, donjons (avec une précision), lignes libres |
| Objets nécessaires | `manual_resources` + `quest_resources` | objet, quantité, recette |
| Récompenses | `rewards` + tables du jeu | XP, kamas, objets, autres (émotes…) |
| Succès, tags, liens utiles, « Prochaine quête du guide complet » | `quest_list`, `guide_*` | navigation |
| Lecteur de quête / overlay | tables du jeu `quests`, `quest_steps`, `quest_objectives`, `npc_messages`… | outil à part (id de quête du jeu) : départ (PNJ, carte), étapes, objectifs typés, dialogues du PNJ |

Il n'y a **ni « jusqu'où » ni « à lier »** sur la page : ce sont nos notes de grimpeurs (`jusqu_ou`, `a_lier`).

### Le suivi étape par étape de Duffus

Il existe, mais il est léger : un clic sur un bloc `qstep` l'estompe (classe `is-dimmed`). L'état vit dans le
`sessionStorage` du navigateur (`duffus.qstepDim.<slug>`, par numéro de bloc) : rien en base, perdu à la fermeture de
l'onglet, sans lien avec la case « quête terminée ». Cocher ou estomper le dernier bloc **ne coche pas** la quête.

## Comparaison avec notre fiche, avant et après F4

| Élément | Avant | Après |
|---|---|---|
| Départ : zone, position [x,y], PNJ | présents mais fragiles (position lue au prix d'un test sur le texte « Départ »), PNJ perdu quand la source n'a pas de position | trois lignes distinctes dans « En bref » ; PNJ gardé même sans coordonnées ; repli sur la ligne du guide (`quest_list`) quand la page n'a pas `startCoords` |
| Position d'une étape de déplacement | seulement dans la liste « Positions », sans lien avec l'étape ; lue dans `data-coords`, parfois resté à « 0,0 » | sur l'étape, bouton `[x,y]` copiable ; on lit le texte du bouton (celui que voit le joueur) |
| Monstres d'un combat | phrase seule + liste globale | ligne par monstre avec sa quantité, dans l'étape |
| Objets « à prévoir » et craft | phrase seule | ligne par objet avec sa quantité, dans l'étape |
| Types d'étapes | donjon, astuce, note, à prévoir, positions, enchaînement : titre « Étape » | titres propres |
| Infos rapides | absentes (colonne non aspirée) | aspirées (`quest_quick.json`) et affichées |
| Suivi par étape | aucun | case par étape pour le grimpeur connecté, en base ; ne coche jamais la quête |
| Fiche DofusDB | objectifs en texte | même structure : ligne par objectif avec genre (monstre, objet, PNJ), nom, quantité, position ; zone, infos rapides, XP et kamas restent vides (DofusDB ne les donne pas) |

## Ce qui a été fait

- `domaine/fiche.py` : `EtapeFiche` gagne `lieux` (positions de l'étape) et `lignes` (`LigneEtape` : genre, texte, nom,
  quantité, x, y) ; `FicheQuete` gagne `depart`, `pnj_depart` et `infos_rapides`. Les fiches déjà en base restent lisibles
  (champs optionnels), mais ne montrent le détail qu'après reconstruction.
- `contenu/fiche_duffus.py` : lecture des positions par étape, des lignes de monstres et d'objets, des types d'étapes manquants,
  des infos rapides.
- `contenu/fiche_dofusdb.py` : même structure à partir des objectifs (combat, apporter un objet, fabriquer, âme, aller voir un PNJ).
- `duffus/` : table `quest_quick` (colonne `quick` de `quest_pages`), fichier `donnees/duffus/2026-10-28/quest_quick.json`
  (1 requête). `Aspiration.lire` tolère son absence (aspirations antérieures).
- Migration `f4_suivi_etapes` (après `e3_fm`) : table `suivi_etape (grimpeur_id, quete_id, ordre)`, RLS activée.
- `POST /api/etapes {quete_id, ordre, faite}` : le grimpeur connecté, sur sa propre fiche, étage ouvert ou terminé ; 404 si l'étape
  n'existe pas, 403 pour un exclu. Réponse : `{ok, faites, total}`. Jamais d'écriture dans `coche_quete` : la case « Faite »
  reste seule à compter pour les points, même quand la dernière étape est cochée (Duffus ne le fait pas non plus).
- Page : cases d'étape visibles seulement quand on peut cocher sa propre fiche ; un admin sans fiche ou un visiteur de la fiche d'un
  autre ne les voit pas. Le numéro d'étape est celui de la fiche : une reconstruction qui change l'ordre des étapes décale
  les cases déjà cochées (accepté : le suivi est personnel et sans points).
- Peu de CSS (quatre règles dans `style.css`) : la direction artistique est refaite à côté.

## Vérification sur de vraies quêtes (base locale reconstruite depuis `donnees/`)

Critère : chaque champ affiché correspond à l'extrait Duffus (`quest_pages.meta`, `content_html`, `rewards`, `quick`).

- Étage 0, « Sous le regard des dieux » : Incarnam, [-3,-3], Ganymède ; Combat solo, Chafer Éclaireur Céleste ×1 et Chafer
  Piquier Céleste ×2 ; 197 XP ; infos rapides « Combat solo ×1 ». Conforme.
- Étage 1, « Balade en forêt » : Astrub, [7,-19], Recrue Mercenaire ; déplacements [-1,-23], [5,-19] et suivants lus sur le
  bouton (et non sur `data-coords="0,0"`) ; 3 × Recrue Mercenaire. Conforme.
- Étage 1, « La coupe des vices » : Astrub, [2,-31], Jeffrey Baratourte ; 4 × Boufton Blanc, 4 × Boufton Noir, 3 × Bouftou,
  1 × Chef de Guerre Bouftou ; 71 795 XP, 1 480 kamas ; infos rapides « Farm ou drop ×1 ». Conforme.
- Étage 2, fiche DofusDB « Manuscrit de Terra Cogita » : PNJ de départ Wally Elconom (la carte de départ n'a pas de
  coordonnées chez DofusDB : position et zone restent vides), 6 étapes, un objectif « Découvrir la carte » avec sa position
  par étape. Champs absents vides, comme prévu.

Tests : `tests/contenu/test_fiche_f4.py` (vraies fiches), `tests/db/test_depot.py` (suivi), `tests/web/test_api.py` (API et page).

## Reconstruction en production

Le `release_command` applique la migration au déploiement. Les fiches se reconstruisent ensuite, étage par étage, sans réseau
(les données sont dans l'image) ; les coches ne sont pas touchées :

    fly ssh console -C 'python -m epreuve.contenu construire --etage 0 --sans-reseau'
    fly ssh console -C 'python -m epreuve.contenu construire --etage 1 --sans-reseau'

Répéter pour chaque étage déjà construit en production (2 et 3 inclus : les fiches DofusDB 26 et 470 sont maintenant en cache).
